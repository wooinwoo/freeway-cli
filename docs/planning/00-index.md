# Freeway 기획과 설계 지식창고

기준일: 2026년 11월 16일 KST  
대상 코드: `689856d9e07815752f8d0d60fd7edcf319755118`  
상태: 협업 설계를 위한 초안. 구현 완료를 의미하지 않는다.

**핵심 차이는 실행 위치다. OpenRouter는 운영 서버에서, Freeway는 사용자 PC에서 요청을 받아 전달한다.**

**먼저 [핵심 기획](18-brief.md)을 읽는다.** OpenRouter에서 안 되는 점, 우리가 가져갈 점, 최종 목표, 두 구조도, 목표 폴더 구조, 분업 순서다. 그 뒤에 [실제 호출 결과](19-live-validation.md)와 상세 설계·태스크를 배치한다.

Freeway는 여러 서비스에 흩어진 개인의 무료 모델 사용 경로를 연결하고, 모델·한도·인증 상태·사용자 선호에 따라 요청을 배분하는 로컬 도구를 목표로 한다. OpenRouter의 모델 목록만 확인해서 제품의 필요성을 판단하지 않는다. OpenCode와 Cline에서 제공하는 무료 사용 경로, 직접 호출할 수 있는 무료 API, 계정별 무료 사용 권한을 함께 비교한다.

현재 확인된 핵심 차이는 다음과 같다.

- OpenRouter는 모델 전환, 공급처 순서, BYOK 키 전환을 이미 제공한다. 이 기능 자체를 다시 만드는 것은 차별화 근거가 약하다.
- OpenCode의 현재 목록에는 `deepseek-v4.1-flash-free`가 있다. OpenRouter의 조회된 DeepSeek 목록에는 무료 모델이 없었다. 같은 모델 계열이라도 서비스별 무료 제공 여부가 다르다.
- Cline은 무료 프로모션을 IDE와 CLI에서 제공하고, Cline API의 무료 사용은 지원하지 않는다고 명시한다. CLI 연동과 추론 API 연동은 같은 기능이 아니다.
- Requesty는 `muse-glimmer-30b`를 무료 경로로 안내한다. Muse라는 이름만으로 Spark, Wonder, Glimmer를 같은 모델로 취급하면 안 된다.
- Ori에서 무료 답변 모델을 지정한 실행에 별도의 유료 Jev 판단 호출이 발생했다. 모델 입력·출력 단가가 0이라는 사실만으로 전체 실행 비용이 0임을 보장할 수 없다.

위 내용의 출처와 실제 실행 범위는 [검증 기록](11-validation-and-evidence.md), [출처 목록](13-sources.md)을 따른다.

회의에서는 먼저 [핵심 기획](18-brief.md)을 읽는다. 실증은 19번, 책임과 인계는 17번, 태스크는 16번을 기준으로 한다. 시스템·한도·API·CLI 상세는 06~09번, docs·설치·출시는 15번에 둔다.

- 로컬 개정 PDF: `exports/20261116_freeway_proposal_v3.pdf`
- 로컬 기존 상세 PDF: `exports/20261116_freeway_plan.pdf`

PDF와 HTML 내보내기는 로컬 산출물이며 Git에는 원본 문서를 보관한다.

개정 PDF는 표지 다음 2~5쪽에 핵심 일곱 항목을 배치한다. 6쪽은 상세 목차, 7쪽부터는 실증·구조·한도·API·CLI·인계·72개 태스크·docs와 배포 상세다. 전체 76쪽이며, 이전 61쪽 PDF와는 다른 개정본이다. 이전 PDF는 당시 기록으로 별도 보존하고 개정본에 중복 첨부하지 않는다. 수정 원본은 각 Markdown, 태스크는 [work-items.json](work-items.json), 그림은 `diagrams/`의 SVG다. 로컬 개정 PDF 검증 기록 `exports/proposal-v3-verification.json`에 구조와 실증·태스크 검사를 남겼다.

회의에서는 01, 03, 05, 10을 먼저 읽는다. 구현 담당자는 04, 06, 07, 08을 이어서 읽는다. 특정 공급처가 실제로 무료인지 판단할 때는 03의 상태와 11의 실행 기록을 함께 본다. 02는 OpenRouter가 이미 해결하는 부분을 중복 개발하지 않기 위한 비교 기준이다.

## 지식창고를 쌓는 방법

1. 기존 주제는 해당 번호의 문서에 반영한다. 날짜가 바뀌었다는 이유로 같은 문서를 복제하지 않는다.
2. 새로운 독립 주제에만 다음 번호를 부여한다. 실험 원자료는 `evidence/`에 날짜와 주제를 붙여 보관한다.
3. 무료 조건, 모델 목록, 인증 방식에는 확인 날짜와 출처를 남긴다. 만료된 프로모션은 삭제하는 대신 종료 상태로 바꾼다.
4. 키·토큰·쿠키·개인 계정 ID·전체 로컬 설정은 저장하지 않는다. 비용·상태 코드·공개 모델 ID만으로 재현 결과를 남긴다.
5. 요구사항 변경은 요구사항 ID, 설계 결정 ID, 영향을 받는 단계와 시험을 함께 수정한다.
6. 이 폴더에는 설계 자료만 쌓는다. 외부 서비스 가입, 유료 결제, 배포를 문서 작성의 일부로 자동 실행하지 않는다.

## 이번 산출물의 경계

이 초안은 제품 기획, 기술 설계, 조사와 검증 계획이다. 모든 후보의 계정 생성과 인증까지 완료한 공급처 인증서는 아니다. 공개된 OpenRouter 계약을 분석하며, 비공개 서버 내부 구현이나 독점 라우팅 알고리즘을 알고 있다고 주장하지 않는다. 기존 Freeway 소스의 런타임 동작은 이 문서 작성만으로 변경되지 않는다.
