# Freeway 제품 목적과 문제 정의

## 제품을 한 문장으로 정의하기

Freeway는 사용자 PC에서 로컬 모델 서버·공식 CLI·외부 무료 API를 연결하고, 사용할 경로를 선택해 요청을 보내는 게이트웨이와 CLI를 목표로 한다. 제공처의 한도에 도달하면 정책에 맞는 다른 경로를 찾되, 비용·모델 변경·기능 차이를 사용자에게 숨기지 않는다.

핵심 차이는 게이트웨이 프로그램의 실행 위치다. OpenRouter는 운영 서버에서, Freeway는 사용자 PC에서 요청을 받아 전달한다. Freeway는 같은 PC의 모델 서버와 설치된 CLI에 직접 연결할 수 있는 구조다. 공식 CLI가 클라우드 모델을 호출하는 경우와 모델 자체가 PC에서 추론하는 경우를 구분하며, 각 경로는 API·CLI 어댑터의 지원 범위를 따른다.

제품의 출발점은 OpenRouter가 자동 전환을 못 한다는 주장이 아니다. **OpenRouter 밖의 무료 사용 경로와 개인의 인증·한도·연결 상태가 서비스마다 흩어져 있다는 문제**다. 무료 접근 경로의 분산(P1), 사용 상태의 분산(P2), 반복되는 연결·선택 작업(P3)을 풀 수 있는지 먼저 검증한다. 문제별 근거, 해결 범위, 중단 조건과 최종 분업은 [제품 공백과 책임 계약](17-product-gap-and-ownership.md)을 따른다.

## 출발점

사용자는 집에서 코딩하거나 모델에 작업을 맡길 때 특정 서비스의 무료 한도에 자주 부딪힌다. 다른 서비스에 같은 모델이나 다른 유용한 무료 모델이 있어도 로그인, 모델 선택, 오류 확인, 대화 이동을 직접 반복해야 한다. 원하는 것은 무료 모델의 링크 모음보다, 이미 자신에게 주어진 무료 사용 기회를 덜 번거롭게 사용하는 방법이다.

사용자가 말한 DeepSeek와 Muse는 이 문제를 검증할 대표 사례다. OpenRouter의 무료 목록에 포함되지 않았다는 사실만으로 다른 서비스에서 무료로 쓸 수 없다고 결론 내리면 안 된다. 반대로 어떤 서비스가 Muse Glimmer를 무료로 제공한다고 Muse Spark나 Wonder도 무료라고 결론 내릴 수 없다.

## 주요 사용자

| 사용자 | 현재 행동 | 원하는 결과 |
| --- | --- | --- |
| 개인 코딩 사용자 | OpenCode나 Cline에서 한도가 끝날 때마다 다른 도구를 연다 | 같은 작업 흐름에서 이용 가능한 무료 경로를 찾는다 |
| 개인 개발자 | 여러 API 키와 무료 조건을 직접 관리한다 | 하나의 로컬 주소와 일관된 API로 모델을 호출한다 |
| CLI 사용자 | 모델 ID와 공급처별 오류를 외워야 한다 | 모델 선택, 연결, 남은 사용 가능성, 대기 시간을 읽기 쉽게 본다 |
| 도구 제작자 | 무료 공급처마다 연동 코드를 반복 작성한다 | 검증된 추론 경로 또는 명확한 작업 위임 인터페이스를 사용한다 |

초기 제품은 한 사람이 자신의 계정으로 자기 컴퓨터에서 사용하는 환경을 우선한다. 조직 공유와 공용 중계 서비스는 인증·데이터 정책·비용·제공처 허용 범위가 달라 별도 제품 범위로 둔다.

## 사용자에게 약속할 결과

- 모델을 선택하면 공급처 경로와 무료 근거를 확인할 수 있다.
- 인증이 필요한 경로는 연결 전부터 알 수 있다.
- 무료 한도 초과와 인증 오류를 구분해 조치 방법을 안내한다.
- 대체 요청 전송 전에 모델 변경 허용 여부와 요청 기능을 확인한다.
- 언제 어떤 경로를 택했고, 다른 경로를 왜 건너뛰었는지 설명할 수 있다.
- 남은 양을 모를 때는 모른다고 표시한다. 로컬 추정치를 공급처의 확정 잔여량처럼 보여 주지 않는다.
- 무료 경로를 찾지 못하면 명확한 오류로 끝낸다. 사용자 모르게 유료 모델을 사용하지 않는다.

## 약속하지 않는 결과

무료 사용량을 무한히 만들 수 없으며, 한 공급처의 계정별 한도를 모델 ID 변경만으로 늘릴 수 있다고 약속하지 않는다. 무료 모델을 묶어도 Claude 유료 플랜과 같은 품질·지연·가용성을 보장하지 않는다. 서로 다른 에이전트의 내부 작업 상태를 손실 없이 자동 이식하는 기능도 초기 약속에 포함하지 않는다.

## 기존 도구로 충분한 조건

다음 조건을 모두 만족한다면 Freeway를 새로 구현하기보다 OpenRouter 설정과 기존 CLI를 사용하면 된다.

1. 원하는 모델이 OpenRouter의 무료 목록에 있거나, 사용자가 가진 공급처 키를 BYOK로 연결할 수 있다.
2. 필요한 계정별 무료 권한이 그 경로에서도 실제로 적용된다.
3. 우선 모델과 대체 모델 목록, 공급처 순서를 미리 정하는 것으로 충분하다.
4. 외부 서비스 전용 CLI의 무료 권한을 통합할 필요가 없다.
5. 현재 UI와 사용량 표시가 사용자의 실무에 충분하다.

OpenRouter가 자동 전환을 제공한다는 것만으로 위 조건이 전부 충족되는 것은 아니다. BYOK는 제공처 인증을 바꾸는 기능이며, 어떤 외부 CLI의 무료 사용 권한도 자동으로 가져오는 기능은 아니다. [OpenRouter BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)

## Freeway를 만들 근거가 되는 조건

| 조건 | 제품 가치 | 먼저 필요한 증거 |
| --- | --- | --- |
| 원하는 무료 모델이 OpenRouter 밖에 있다 | 접근 가능한 무료 모델 범위를 넓힌다 | 모델·날짜·계정별 무료 경로와 성공 호출 |
| 무료 경로가 공식 CLI에 묶여 있다 | 도구별 연결을 통일한다 | 공식 headless 또는 서버 인터페이스와 자동화 허용 범위 |
| 무료 한도 기준이 공급처마다 다르다 | 한도에 맞춰 경로를 배분한다 | 단위·범위·리셋·공식 조회 가능성 |
| 사용자마다 모델 선호와 대체 허용 범위가 다르다 | 간단한 정책으로 선택을 제어한다 | 실제 사용자 시나리오와 explain 결과 |
| 기본 CLI가 보조 유료 요청을 만든다 | 전체 실행의 비용을 통제한다 | 주 모델과 보조 호출을 분리한 비용 기록 |

## 용어

| 용어 | 정의 | 예 |
| --- | --- | --- |
| 모델 | 특정 버전과 기능을 가진 추론 대상 | DeepSeek V4.1 Flash, Muse Glimmer 30B |
| 공급처 | 요청을 실제로 받거나 중계하는 서비스 | NVIDIA, Requesty, OpenCode |
| 경로 | 모델·접속 방식·계정 권한을 결합한 실행 선택지 | OpenCode CLI의 DeepSeek 무료 경로 |
| 추론 API | 메시지와 도구 정의를 받아 모델 응답을 반환하는 인터페이스 | Chat Completions |
| CLI 브리지 | 공식 CLI 또는 서버를 제어하는 연동 | OpenCode headless server |
| 작업 위임 | 외부 에이전트에 작업 자체를 맡기는 방식 | Cline에게 코드 검토 작업 전달 |
| 무료 권한 | 서비스가 계정·IP·프로모션 조건으로 제공하는 사용량 | 일 200회, 시간당 200회 |

## 대표 시나리오

### 같은 모델을 계속 쓰기

사용자가 DeepSeek의 특정 버전을 고른다. 경로 A가 사용할 수 없으면, 동일한 버전으로 확인된 무료 경로 B를 찾는다. 경로 B가 다른 모델 버전이거나 도구 호출을 지원하지 않는다면 동일 모델 대체로 취급하지 않는다. 다른 모델 사용은 사용자가 Auto 또는 대체 정책을 켰을 때만 허용한다.

### 무료 모델 중 적합한 것을 쓰기

사용자가 `free/auto`를 고른다. 요청이 도구 호출을 포함하면 실제로 도구 호출이 가능한 무료 추론 경로만 후보가 된다. 잔여량과 상태를 비교하고, 사용자 선호 순서에 따라 선택한다. 특정 모델로 바뀔 수 있다는 사실과 실제 선택 모델을 결과에 남긴다.

### 서비스의 CLI 무료 권한 사용하기

Cline의 무료 권한이 공식 CLI에서만 제공되면 Freeway는 그 경로를 추론 API와 구분한다. 우선 독립적인 텍스트 작업을 맡기는 경로로 검증한다. 외부 에이전트가 임의의 OpenAI 도구 호출을 반환할 수 있는지 확인하기 전에는 코딩 클라이언트용 호환 API에 섞지 않는다.

## 성공 지표 제안

첫 번째 지표는 공급처 개수가 아니라, 동일한 테스트 작업을 유료 모델로 넘어가지 않고 완료한 비율이다. 함께 측정할 값은 연결 완료 시간, 한도 초과 후 복구 성공률, 첫 토큰 지연, 사용자가 직접 모델을 바꾼 횟수, 비용이 확인되지 않은 실행 비율이다.

초기 목표 수치는 실제 기준 측정 후 정한다. 무료 한도가 아직 검증되지 않은 공급처를 늘려 등록 모델 수만 부풀리지 않는다.

## 제품 중단 또는 축소 조건

- 목표 무료 경로가 OpenRouter와 기존 도구 설정만으로 모두 충족되면 자체 라우터 범위를 축소한다.
- 주요 공급처가 외부 자동화를 지원하지 않으면 해당 경로를 제외하고 목표 달성 가능성을 다시 판단한다.
- 사용자가 원하는 코딩 기능을 CLI 브리지에서 보존할 수 없으면 텍스트 위임과 코딩 추론 API를 분리한다.
- 공식 한도나 상태 조회가 없으면 정확한 최적화를 약속하지 않고, 관측 기반의 우선순위와 쿨다운부터 제공한다.
