## 최신 실증 결과

2026년 11월 16일 추가 실행으로 OpenRouter 무료 응답·429 대조군·무료 대체 성공·비용 0 USD, OpenCode 무료 할당 소진, Cline 재로그인 뒤 해당 모델 거절과 공식 CLI의 프로모션 종료 안내를 확인했다. 최신 기획은 [실제 호출 결과](19-live-validation.md)를 따른다. 아래 기존 실행 기록은 당시 관측을 보존한다.

## 비용 확인 기록

```json
{
  "answer_model": "nvidia/nemotron-3.5-lightning:free",
  "answer_cost_usd": 0,
  "auxiliary_model": "typesafe/jev-1.14-20261014",
  "auxiliary_cost_usd": 0.000057036,
  "account_key_usage_usd": 0.000057036
}
```

금액은 해당 실행 후 확인한 계정 키 사용량과 generation 메타데이터를 대조했다. 보조 호출을 단순한 화면 추정치라고만 설명할 수 없는 근거다. 카드 등록 여부나 무료 크레딧이 남았는지는 사용량 발생과 별개의 문제다.

직접 API의 무료 응답과 정상 모델 대체 요청은 각각 cost 0을 반환했다. 이 차이는 이번 Ori 실행 경로에서 관찰한 결과이며, OpenRouter의 모든 클라이언트가 추가 비용을 만든다는 뜻은 아니다.

## 재현 명령의 성격

다음 두 명령은 읽기 전용 설치·인증 점검이다.

```bash
/home/rst010/.local/bin/ori --version
/home/rst010/.local/bin/ori doctor --json
```

다음 명령은 실제 모델 요청을 전송한다. 무료 모델을 지정하더라도 Ori 내부의 별도 호출까지 무료라고 보장하지 않으므로 기본 비용 회귀 시험 명령으로 사용하지 않는다.

```bash
/home/rst010/.local/bin/ori code --model openrouter/free --approvals manual -p 'Reply exactly FREE_OK.'
```

OpenCode의 목록 확인 명령은 다음과 같다.

```bash
/home/rst010/.local/bin/opencode models opencode
```

정확한 재현에는 CLI 버전, 계정 권한, 현재 무료 카탈로그, 지역, 네트워크 조건이 필요하다. 인증 키를 재현 문서의 명령행에 넣지 않는다. 임시 진단에서 사용한 비공개 credential helper를 제품 인증 API로 채택하지 않는다.

## 공급처 계약 시험

각 활성 어댑터에는 목록, 최소 텍스트, system 메시지, 멀티턴, stream, 오류, usage, 취소를 기록한다. 도구 지원 경로에는 단일 도구, 여러 도구, 인자 분할, 도구 결과 후 응답을 추가한다. 재현용 fixture에서는 비밀과 개인 데이터를 제거한다.

문서상 기능과 실제 기능이 다르면 경로를 비활성화하거나 capability를 낮춘다. 실패 시험을 통과시키기 위해 실제 공급처 한도를 무차별 소진하지 않는다. 429는 가짜 어댑터로 정책을 재현하고, 실제 공급처 제한은 발생했을 때 범위와 헤더를 관측한다.

## 품질 비교

대표 작업은 코드 설명, 버그 원인 찾기, 변경 검토, 작은 수정안 작성으로 제한한다. 정답이 있는 검증과 사람이 판단해야 할 품질을 구분한다. 단순히 `OK` 문자열을 받았다고 코딩 품질이 충분하다고 결론 내리지 않는다.

각 작업에서 완료 여부, 도구 계약 준수, 첫 토큰 지연, 전체 시간, 실제 모델, 비용, 사용량, 사용자 재개입 횟수를 기록한다. 모델 순위는 측정한 과제와 표본에 한정한다.

## 문서 자체의 검증

번호 문서와 상대 링크, 요구사항 ID의 연결, 기존 기능과 제안 기능 구분, 근거가 없는 무료 주장, 계정 비밀 포함 여부를 검사한다. 독립 검토에서는 원래 사용자 요구와 공개 자료를 기준으로 제품 범위가 다시 OpenRouter 안으로 좁아지지 않았는지 확인한다.

전체 공급처의 실제 연동 완료가 이 설계 문서의 완료 조건은 아니다. 반대로 문서가 완성됐다는 이유로 M0의 공급처 검증 게이트를 통과한 것으로 표시하지 않는다.

## 이번 설계 문서의 독립 검토 결과

독립 읽기 전용 검토에서 Store 초기화 전 작성자 잠금, 공급처 스냅샷과 로컬 소비의 정산 기준, read-only 작업의 실행 전 차단을 보완했다. 관련 요구사항과 시험 T 023부터 T 025까지 연결했으며, 변경 영역을 한 번 집중 재검토했다. 남은 High 또는 Critical 설계 문제는 보고되지 않았다. 이 결과는 구현 시험이나 PDF 레이아웃 검사를 대신하지 않는다.
