# 현재 Freeway 코드와 설계 차이

기존 구현은 저장소 루트의 `POC/`로 이동했다. 이 문서의 구현 파일 경로는 `POC/` 내부를 기준으로 읽는다.

## 기준

분석 대상은 커밋 `689856d9e07815752f8d0d60fd7edcf319755118`이다. 현재 패키지는 Node.js ESM 기반이고 외부 npm 의존성 없이 동작하도록 작성되어 있다. 이 문서는 정적 코드 관찰과 이번 호출 결과를 구분하며, 전체 코드 감사를 대신하지 않는다.

## 현재 모듈 구조

| 파일 | 현재 책임 | 재사용 방향 |
| --- | --- | --- |
| `server.mjs` | loopback HTTP, 관리 API, 호환 API, 인증, 스트리밍 | API 경계를 유지하고 코어에 선택 판단을 위임한다 |
| `src/catalog.mjs` | 공급처 정의, 무료 판별, 준비 상태 | 가격 근거와 권한·상태·한도를 분리한다 |
| `src/adapters.mjs` | 모델 동기화, OpenAI 호환 요청 | 공급처 계약과 파라미터 검증을 강화한다 |
| `src/engine.mjs` | 후보 생성, 정렬, 대체 요청, 기록 | 라우팅 계획과 실행을 분리한다 |
| `src/store.mjs` | JSON 상태, 키 암호화, 사용량·예약 | 단일 프로세스 범위에서 재사용하고 동시성 요구에 따라 전환한다 |
| `src/opencode.mjs` | 로컬 OpenCode 서버 제어, 모델 조회, 텍스트 응답 변환 | 텍스트 브리지 범위를 명시한다 |
| `src/model-groups.mjs` | 여러 경로의 모델 묶기 | 버전 식별과 경로별 기능 판단을 유지한다 |
| `src/chats.mjs` | 로컬 대화 이력 | API의 무상태 요청과 CLI 저장 이력을 구분한다 |
| `src/mcp.mjs` | 모델 목록과 텍스트 위임 도구 | 기존 read-only 텍스트 위임 의미를 보존한다 |
| `cli.mjs`, `src/client.mjs` | 명령 해석과 게이트웨이 호출 | CLI를 코어의 얇은 클라이언트로 유지한다 |
| `src/tui.mjs`, `src/terminal-ui.mjs` | 터미널 화면과 대화 | 기존 UI를 정책·상태 표시와 연결한다 |
| `public/` | 브라우저 대화와 관리 화면 | 초기 전면 재작성 범위에 넣지 않는다 |

## 이미 구현된 기능

현재 코드는 단순 프롬프트 한 번을 보내는 예제를 넘어선다. 공급처별 무료 후보를 만들고, 모델을 묶고, 사용자 선호와 공급처 우선순위에 따라 요청한다. 모델 선택에 따라 같은 모델의 경로를 먼저 시도하거나 Auto에서 다른 모델로 넘어간다.

요청 전 예약으로 요청 수를 늘리고, 결과 후 토큰과 지연을 기록한다. 한도 초과와 일부 인증·업스트림 오류에는 쿨다운을 둔다. 응답 청크를 하나라도 내보낸 뒤에는 대체 경로로 넘어가지 않는 방어도 있다.

관리 API와 추론 API는 인증 방식을 구분한다. 서버는 `127.0.0.1`에 바인딩하며 Host와 Origin을 검사한다. API 키와 저장된 대화는 로컬 암호화 경계를 사용한다. 따라서 설계를 다시 한다고 이 기능을 모두 버릴 이유는 없다.

## 부족한 점과 요구사항 연결

| 차이 | 코드 근거 | 실제 영향 | 우선순위 |
| --- | --- | --- | --- |
| 실사용량 기반의 동적 순서가 없다 | `Engine.candidates`는 설정 우선순위로 정렬 | 남은 한도나 실패율에 따라 자동 배분하지 못한다 | P0 |
| 사용량이 로컬 관측이다 | `Store.buckets`, `capacity` | 다른 도구에서 쓴 양을 확정 잔여량에 반영하지 못한다 | P0 |
| 한도 범위가 공급처 ID 중심이다 | usage가 `provider.id` 기준 | 모델별·계정별·IP별·공유 상위 풀을 정확히 표현하기 어렵다 | P0 |
| 무료 판별이 전체 실행 비용까지 보지 않는다 | `freeModel`의 단가·allowlist 판정 | 보조 요청·프로모션 만료·별도 유료 기능을 놓칠 수 있다 | P0 |
| 일부 기능을 기본 지원으로 추정한다 | `normalizeModel`의 tools 기본값 | 실제 미지원 경로로 코딩 요청이 갈 수 있다 | P0 |
| CLI 브리지와 추론 어댑터가 같은 실행 경로에 있다 | `Engine.complete`의 OpenCode 분기 | 텍스트 결과와 임의 도구 호출 호환성을 혼동할 수 있다 | P0 |
| OpenCode 브리지는 도구를 차단한다 | `deniedTools`, 텍스트 이벤트 변환 | OpenCode의 코딩 에이전트 전체 기능을 제공하는 브리지가 아니다 | P0 |
| 요청 파라미터 보존 범위가 제한적이다 | `adapters.mjs`의 `allowed` | 전달되지 않는 파라미터가 생길 수 있어 계약 명시가 필요하다 | P1 |
| Cline 어댑터가 없다 | 공급처 정의와 모듈 목록 | 사용자가 원하는 대표 무료 경로 하나가 미구현이다 | P0 |
| 파일 저장의 다중 프로세스 계약이 없다 | `state.json.tmp` 저장과 메모리 예약 | 별도 프로세스가 같은 상태를 수정할 때 원자성이 보장되지 않는다 | P1 |
| 실패 원인이 정책 단위로 충분히 분리되지 않는다 | provider 전체 쿨다운 | 특정 모델 문제로 전체 공급처를 배제할 수 있다 | P1 |

무료 판별과 도구 지원 기본값은 전체 보안 취약점 판정이 아니라 설계상의 신뢰 경계 문제다. 실제 수정 전에 공급처별 재현 시험을 먼저 만든다.

## 테스트와 패키징의 현 상태

`package.json`에는 `node --test tests/*.test.mjs`와 `node scripts/check.mjs`가 등록되어 있다. 그러나 확인한 추적 파일 목록에는 `tests/`와 `scripts/check.mjs`가 없다. 명령이 정의되어 있다는 이유만으로 검증 체계가 갖춰졌다고 보고할 수 없다.

Windows 설치 스크립트와 명령 래퍼는 존재한다. 실제 릴리스 산출물의 파일 구성, 체크섬 검증, 업데이트·롤백, 깨끗한 PC에서의 첫 실행은 별도 배포 검증 항목이다. 문서만으로 설치 신뢰성을 확정하지 않는다.

## POC를 유지하며 바꿀 순서

1. 대표 공급처 경로의 실제 입출력을 기록하고, 현재 동작을 보존할 최소 시험을 확보한다.
2. 기존 ID와 명령은 유지하면서 `routeKind`, 가격 근거, 권한과 기능 상태를 추가한다.
3. 후보 생성에서 정책 판단을 추출해 `plan` 결과를 만든다. 이 단계는 모델 호출 없이 검증할 수 있어야 한다.
4. 실행기가 계획에 따라 예약·호출·기록을 수행하도록 책임을 정리한다.
5. API가 보장하는 기능을 검증한 경로만 호환 엔드포인트에 노출한다.
6. Cline처럼 작업 위임 계약이 다른 경로는 별도 명령과 작업 결과로 추가한다.
7. 이후 동시성 근거가 생기면 상태 저장을 SQLite 트랜잭션으로 전환한다.

## 당장 하지 않을 일

전체 Node 코드를 Go로 옮기고 TUI를 Rust로 새로 만드는 일은 핵심 무료 경로의 실현 가능성을 검증하지 못한다. 언어 전환은 별도 결정으로 남기며, 공급처 연동 계약과 라우팅 정책이 먼저 안정되어야 한다. 기존 브라우저 UI와 MCP를 동시에 재설계하는 것도 초기 범위에서 제외한다.

## 구현 착수 전 고정할 기준선

지원 OS, 기본 CLI 명령, 외부 API 경로, 기존 모델 ID 해석, 저장 데이터 위치, 유료 대체 금지, 스트림 시작 후 전환 금지, 취소 전달, 키 마스킹을 기준선으로 잡는다. 그중 무엇을 변경하는지 단계별로 명시해야 회귀를 판단할 수 있다.
