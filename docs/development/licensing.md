# 라이선스 선택과 재사용 기준

확인일: 2026-11-16. Freeway가 배포할 권리를 가진 코드와 자체 작성 문서는 저장소 루트의 [MIT License](../../LICENSE)를 따릅니다. 아래 설명은 그 선택과 제3자 자료 처리 기준이며, LICENSE 원문에 별도의 금지 조건을 추가하지 않습니다.

## 1. MIT를 선택한 이유

프로젝트의 현재 목적은 개인 PC에서 사용할 도구를 공개하고, 다른 사람이 검토·수정·기여·재사용하기 쉽게 하는 것입니다. 무료 개인 사용만을 허용하거나 모든 파생 코드를 반드시 공개하도록 강제하는 요구는 두지 않았습니다.

따라서 저작권과 라이선스 고지를 유지하면서 사용·수정·재배포할 수 있는 MIT를 선택했습니다. 다른 프로젝트의 코드를 그대로 가져오기 쉬운지와 우리 코드의 공개 조건은 별개로 판단합니다. [MIT 원문](https://opensource.org/license/mit)

## 2. 사용자가 할 수 있는 일과 지킬 조건

| 항목 | MIT 선택의 의미 |
| --- | --- |
| 개인·회사 사용 | 모두 허용됩니다. |
| 수정·포크·재배포 | 허용됩니다. 원래 저작권·허가 고지를 유지해야 합니다. |
| 유료 판매·상업 서비스·비공개 제품에 사용 | 허용됩니다. 프로젝트가 돈을 받지 않는다는 운영 방침과는 별개입니다. |
| 수정본 전체 공개 | MIT가 의무로 요구하지 않습니다. |
| 저작권 양도 | 라이선스 부여만으로 원 저작권이 프로젝트나 이용자에게 넘어가지는 않습니다. |
| 보증·책임 | LICENSE의 무보증·책임 제한 문구를 따릅니다. 이를 모든 국가·상황에서 책임이 무조건 없다는 뜻으로 확대하지 않습니다. |

‘상업적 이용 금지’나 ‘포크 판매 금지’를 추가하면 표준 MIT가 아닙니다. OSI의 오픈소스 정의도 사업 분야에 따른 이용 제한을 허용하지 않습니다. 그런 정책을 원한다면 이 문서에 예외를 끼워 넣기보다 프로젝트의 배포 목적과 라이선스 선택부터 다시 검토해야 합니다. [OSI 정의 1·6항](https://opensource.org/osd)

MIT에는 Apache-2.0의 3항과 같은 명시적 특허 허여 조항이 없습니다. 이 비교는 ‘MIT에서는 특허 문제를 전부 면책한다’거나 ‘어떠한 특허 권리도 인정될 수 없다’는 결론이 아닙니다. [Apache-2.0 3항](https://www.apache.org/licenses/LICENSE-2.0)

## 3. 비교한 대안

| 후보 | 특징 | 이번 선택에서의 판단 |
| --- | --- | --- |
| MIT | 짧은 허용형 라이선스. 고지 유지와 무보증 문구를 중심으로 재사용을 허용 | 현재의 단순 공개·기여 목적에 사용 |
| Apache-2.0 | 허용형이며 명시적 특허 허여·종료 조건, 변경 표시와 NOTICE 처리 규정이 있음 | 특허와 기업 기여 조건을 명시하는 요구가 커지면 검토할 대안 |
| AGPL-3.0 | copyleft 조건이 있으며, 수정한 네트워크 프로그램에는 해당 이용자에게 소스를 제공하는 조건도 있음 | 파생·수정본의 소스 제공을 요구하는 목적이라면 검토할 대안 |

AGPL도 상업적 이용 자체를 금지하는 라이선스가 아닙니다. 또한 네트워크 서비스 여부 하나만으로 모든 의무가 사라지거나 생기는 것으로 단순화하지 않습니다. 배포·수정·결합의 실제 형태를 기준으로 해당 조항을 읽어야 합니다. [Apache-2.0 원문](https://www.apache.org/licenses/LICENSE-2.0), [AGPL-3.0 원문 4·5·6·13항](https://www.gnu.org/licenses/agpl-3.0.en.html)

## 4. 원본·POC·기여 코드의 범위

루트 LICENSE는 프로젝트가 허락할 권리를 가진 부분에 적용합니다. `POC/`라는 폴더명이나 코드의 이동은 타인의 권리를 없애거나 새로 만들지 않습니다. 기존 저작권·라이선스 고지가 있는 파일은 그 고지를 보존합니다. 라이선스를 새로 추가했다는 이유로 권리 출처가 불명확한 외부 코드를 MIT로 바꿀 수 없습니다.

현재 Go 백엔드 틀은 새로 작성한 진입점과 표준 라이브러리만 사용하며 외부 Go 모듈은 없습니다. 별도 CLI 모듈에는 Nekot에서 추린 TUI 코드와 Bubble Tea·Bubbles·Lip Gloss 의존성이 있습니다. 원본 커밋·수정 파일·보존 고지는 [제3자 고지](../../THIRD_PARTY_NOTICES.md)에 기록합니다. 조사 목적으로 클론한 LocalRouter·LiteLLM·CLIProxyAPI의 구현은 포함하지 않습니다. 기존 POC의 `package.json`에는 외부 npm 의존성이 선언되어 있지 않지만, 이것만으로 전체 파일의 저작권 출처나 과거 릴리스에 포함된 모든 구성요소를 증명하는 것은 아닙니다.

기여자는 자신이 제출할 권리가 있는 부분을 MIT 조건으로 제공합니다. 저작권 양도는 요구하지 않습니다. 외부 코드를 포함하면 원래 라이선스와 고지를 별도로 제출해야 합니다. [기여 방법](../../CONTRIBUTING.md)

## 5. 조사한 프로젝트에서 코드를 가져올 때

아래는 조사 시 고정한 커밋의 실제 고지입니다. 기능이나 구조를 비교한 문서와 구현을 복사해 배포하는 일은 구분합니다.

| 프로젝트 | 확인한 고지 | 재사용 시 적용할 기준 |

| LocalRouter | `AGPL-3.0-or-later` | 원본·수정분의 의무와 결합 방식부터 검토합니다. MIT 고지만 붙여 흡수하지 않습니다. |

근거: [LocalRouter 고정 커밋](https://github.com/LocalRouter/LocalRouter/blob/5ecfce7d74f207965278c490c825b730fd84edbc/Cargo.toml), [CLIProxyAPI 고정 커밋](https://github.com/router-for-me/CLIProxyAPI/blob/14144df573c77e8e0e1eeaa450d3e63a068372df/LICENSE), [LiteLLM 고정 커밋](https://github.com/BerriAI/litellm/blob/d034fb681ca296a0f082a224043eda62a2ce82d4/LICENSE).

외부 프로그램을 HTTP나 subprocess로 연결한다는 사실만으로 라이선스 적용 범위를 일괄 판정하지 않습니다. 어떤 코드와 실행 파일을 실제로 배포하는지, 변경했는지, 결합 방식이 무엇인지에 따라 확인합니다.

## 6. 소프트웨어 라이선스와 서비스·모델 조건

Freeway의 MIT는 공급자의 계정·OAuth·API·무료 할당이나 모델 가중치의 이용 조건을 바꾸지 않습니다. 이 저장소의 라이선스가 업체의 접속 권한이나 무료 사용량을 제공하는 것도 아닙니다. 공급처 연결 문서에는 해당 공식 인터페이스·인증 방식·지원 기능·무료 조건의 근거를 별도로 기록합니다.

브랜드·로고·개인 데이터·대화 원문·공급처의 콘텐츠에 대해 Freeway가 보유하지 않은 권리를 MIT라는 이유로 부여한다고 설명하지 않습니다.

## 7. 소스 공개와 실행 파일 배포

현재 GitHub에 올리는 것은 개발 틀·기획·기존 POC입니다. Go 실행 파일, Node 런타임, 모델 가중치나 외부 CLI 실행 파일을 새로 배포하지 않습니다. 임시 빌드 결과도 커밋하지 않습니다.

향후 실행 파일을 배포할 때는 프로젝트 LICENSE와 실제 포함 구성요소의 원래 고지·라이선스를 배포 묶음에 넣습니다. Go 표준 라이브러리와 Node 런타임의 고지, 외부 모듈의 NOTICE·라이선스, 소스 제공 조건을 실제 버전과 파일 기준으로 확인합니다. 기록 위치는 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)이며, 다른 버전의 고지를 추측해서 대신 쓰지 않습니다.

이 문서는 라이선스 선택 근거와 현재 확인 범위를 남깁니다. 과거 릴리스 전체나 앞으로 추가될 의존성의 적합성을 미리 보증하는 문서는 아닙니다.
